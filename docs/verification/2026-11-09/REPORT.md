요청: "소예배실 앞에도 스크린으로 바꿔줘" → "스크린 안엔 이걸 해줘" (사용자가 준 그림: '서로 짐을 나눠지는 공동체')

## 바꾼 것 (index.html, 2층 소예배실 블록)
- 앞(북쪽) 원목 벽 가운데에 본당처럼 검은 테두리 화면을 걺: 16:9, 2.3m × 1.29m, 아래 끝 바닥에서 0.74m (강대상 윗면 0.44m보다 위라 가리지 않음)
- 화면 그림: 사용자가 준 그림을 1280×720 JPG로 줄여 `assets/screen/share-burdens.jpg`로 넣음 (못 불러오면 같은 글씨를 코드로 그린 그림)
- 십자가는 화면 오른쪽(동쪽) 벽 x -7.75로 옮기고(크기·높이 그대로), 뒤에 은은한 빛 (밤에 더 밝음). 왼쪽은 디지털 피아노
- 화면 판은 누르기·걷기·카메라 판정에서 빠짐

# 걸을 때 버벅임 검토 (사용자 "캐릭터가 움직일 때 약간 버벅거려, 서버가 무거워져서인지")

## 결론
- 서버 때문이 아님: 사이트(GitHub Pages)는 처음 열 때 파일만 받고, 걷는 동안엔 주고받는 것이 없음. 함께 있는 사람 위치(Supabase)는 아주 작은 글이라 걷기와 무관
- 휴대폰이 한 화면마다 그리는 양 + 걷다가 처음 보는 것의 셰이더(그리기 프로그램)를 그 자리에서 만드는 멈칫이 원인

## 잰 것 (tools/walk-check/perf.cjs, 바꾸기 전 → 후, 한 화면 그리기 호출 수)
| 장소 | 전 | 후 |
|---|---|---|
| 1층 로비 | 647 | 264 |
| 1층 필로티 | 1013 | 341 |
| 지하 본당 | 600 | 556 |
| 2층 소예배실 | 711 | 409 |
| 3층 식당 | 675 | 357 |
| 4층 목양실·옥상 | 1998 | 672 |
- 걷는 동안 새로 만든 셰이더: 장소마다 1~3개, 벽이 투명해질 때마다 더 (벽 가림 시험 11개) → 0개

## 고친 것 (index.html)
1. 지금 층 가구만 그림: 다른 층 가구(3층 1,473개 등)는 바닥·벽에 가려 안 보이는데도 매 화면 그리고 그림자까지 만들었음 → `goToTourStep`에서 그 층 무리만 보이게 (1층 필로티 가구는 지하가 아니면 늘 둠). 무리마다 다른 층 높이의 물체가 없음을 확인
2. 층을 옮긴 직후(엘리베이터 화면이 가린 동안) 그 층 셰이더를 미리 만듦 (`warmShaders`: 평소 모양 + 벽이 투명해질 때 모양)
3. 벽이 캐릭터를 가릴 때 쓰는 투명 재질을 물체마다 한 번 만들어 계속 씀 (예전엔 매번 새로 만들고 버려서 셰이더를 또 만들었음)
4. 매 화면 카메라 광선은 보이는 무리에만 쏨

## 확인
- 모든 장소(8곳) 처음 화면을 바꾸기 전과 낮 · 밤 모두 비교: 바뀐 픽셀 0 (tools/walk-check/cmpview.cjs)
- 벽 가림 → 투명 → 돌아옴 → 다시 투명: 잘 됨, 새 셰이더 0 (tools/walk-check/fadewalk.cjs)
- 층마다 걷기 · 의자 수 그대로 (본당 112 · 3층 83 · 2층 50 · 4층 19), 목양실 길 · 앉기, 소예배실 의자 30 · 기도 그대로, 오류 없음
- 남은 것: 실제 휴대폰에서 느낌 확인. 그래도 버벅이면 다음 단계로 화면 선명도(픽셀 비율 2 → 1.5)를 낮추는 방법이 있음 (화면이 아주 조금 덜 선명해짐)
