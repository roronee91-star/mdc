## 0. 먼저 읽을 것 (사용자와 일하는 방식)

- 사용자(혜연)는 **코딩을 전혀 모른다**. 한국어, 쉬운 말, 짧게. **한 번에 질문은 딱 하나만.**
- 한 단계가 끝나면 결과를 보여주고 **"마음에 들어요?"** 라고 묻고 다음 단계로 간다.
- 사용자가 해야 할 일은 "무엇을 누르는지"까지 하나씩 알려준다. 막히면 화면 캡처를 부탁한다.
- 사용자는 코드를 직접 고치지 않는다. 값(주소, 키 등)은 사용자가 보내주면 **내가 index.html에 직접 넣어서 파일을 다시 준다.**
- 원래 지시서는 `docs/original_instructions.txt`에 그대로 있다. **8단계 진행 순서 + Supabase 안내 규칙 + 올리기 안내 규칙**이 들어 있으니 반드시 읽을 것.
- 솔직하고 구체적인 평가를 선호한다. 모호한 답보다 수치와 근거.
- 이 채팅에서는 사용자가 "작업할까요?"에 "응" 하면 진행하는 방식이었다. 큰 변경 전에는 한 줄로 확인하는 편이 안전하다.

## 1. 프로젝트 목표

물댄동산교회(신축 예정) 건물을 3D 온라인 공간으로 만들어, **성도들이 같은 방에 들어와 서로 인사하고, 소그룹실·식당에 앉아보고, 밥 먹고, 기도하고, 기도제목을 써서 올리는** 사이트.

지시서의 8단계 중 현재 위치:

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 컨셉 | 완료 — "물댄동산교회 성도 모임 공간" |
| 2 | 3D 장면 (index.html, 단일 파일) | **대부분 완료** (GLB 건물 + 캐릭터 + 3층 식당/소그룹실 + 본당 보정) |
| 3 | 소리 (코드로 만든 배경음, 켜고 끄기) | 기존 코드에 찬양 반주(사인파 화음)와 토글 버튼 있음. 유지 |
| 4 | 내가 들어가기 (걷기·앉기·행동, 폰은 조이스틱) | 클릭 이동, 앉기, 기도, 식사, 소그룹실 앉기 있음. **폰 조이스틱·건배는 아직 없음** |
| 5 | 사진 등록 (얼굴이 캐릭터에 붙음) | 미착수 |
| 6 | 친구랑 만나기 (Supabase Realtime: 닉네임·말풍선·건배) | 미착수. 기도제목 쓰기/올리기도 여기서 저장소 필요 |
| 7 | 올리기 (Netlify Drop) | 미착수 |
| 8 | 접속 확인 | 미착수 |

사용자가 원하는 기능(이번 대화에서 확정): 둘러보기·인사, 소그룹실/식당에 앉기, 밥먹기, 기도하기, **기도제목 쓰기(올릴 수 있게)**.

## 2. 파일 구성

```
church-site/
├─ index.html                               ← 지금 작업본 (church_tour.html에서 이어 만듦)
├─ church-model-release-20261104.glb        ← 건물 3D 모델 (사용자 제공, 수정하지 않음)
├─ vendor/three/…                           ← 사용자 컴퓨터에만 있음. 이 폴더는 내가 받지 못했다
├─ HANDOFF.md                               ← 이 문서
├─ docs/original_instructions.txt           ← 사용자의 원래 지시서(8단계 규칙)
├─ original/church_tour.html                ← 사용자가 처음 준 원본(비교용)
├─ preview/                                 ← 위에서 본 배치 그림 (검증용 PNG)
└─ tools/                                   ← 검증/생성에 쓴 스크립트 (아래 7번)
```

- `index.html`이 **기준(source of truth)**이다. tools/ 안의 조각 파일은 index.html을 만들 때 쓴 것이라 참고용이다.
- `vendor/three/`: `three.module.js`, `loaders/GLTFLoader.js`, `controls/OrbitControls.js`가 `index.html`의 import map과 import 경로(`./vendor/three/...`)로 쓰인다. **사용자에게 이 폴더를 받아야 직접 화면 확인이 된다.** 받지 못하면 CDN 버전으로 바꿔 쓸 수 있다(미리보기 링크가 그 방식).
- **도면 PDF(5.7MB)는 포함하지 않았다.** 첫 장에 "(주)아벨건축사사무소 설계, 양민수 교수 저작권 — 건축물의 형태·평면·색상·재료 임의 수정 또는 변경 금지" 문구가 있다. 그래서 (a) 건물 형태는 GLB 그대로 두고 가구·장식만 얹는다, (b) 도면 PDF를 인터넷에 올리지 않는다.
- 브라우저 미리보기(비공개 링크, 사용자 계정 전용): https://claude.ai/artifact/GDSGLEmBdacVRhCUyWrUGC
  - index.html과 같은 코드인데 three를 jsdelivr(0.160.0)에서 받고 GLB를 파일 안에 넣어 둔 버전이다. 배포용이 아니라 확인용.
- ES 모듈과 GLB 로딩은 `file://`로 열면 브라우저가 막는다. 로컬에서 볼 때는 `python3 -m http.server` 같은 간단한 서버가 필요하다. (사용자가 이미 어떻게 열고 있는지는 아직 모른다. 물어볼 것.)

## 3. 건물/도면 사실

### 3.1 층 구성 (도면 기준)
- **지하 1층:** 본당(B102), 유아실=자모실(B103), 방송실=엔지니어룸(B104), 준비실, 계단실 #1(B105)·#2(B106), 정화조 등. 본당 바닥은 부채꼴로 단차가 있다.
- **1층:** 주차장 15대, 계단실, 전실 (실내 방 없음)
- **2층:** 사무실(201), 교사실(202), 교육관-1(203), 학생부실(204), 청년부실(205), 성가대실(206), 홀/복도(207)
- **3층:** 식당/예배실(301, 테이블이 줄지어 그려짐), 주방(302), 소그룹실 1·2·3(303–305), 여화장실(306), 창고
- **4층:** 목양실(401), 교육관-1(402), 그룹실(403), 옥상 정원
- 도면의 본당에는 의자가 그려져 있지 않다. 좌석 수는 도면으로 알 수 없다.

### 3.2 GLB가 도면보다 작다 (중요)
- 도면 3층 가로 24.85m ↔ GLB 12.4m (정확히 절반). 세로는 도면 18.45m ↔ GLB 17.5m. 지하 본당은 도면 26.6×22.4m ↔ GLB 약 14×18m. 면적으로 도면의 약 42%.
- 캐릭터가 높이 1m(대략 사람의 절반)라서 **가구도 절반 크기**로 맞췄다. (의자 앉는 면 높이 0.22m, 식탁 높이 0.38m)
- 사용자 결정: **"A. 지금 GLB에 맞춰서 줄이기"** 를 택했다. 건물을 도면 크기(가로 2배)로 키우는 B안은 하지 않았다. 필요하면 나중에 다시 논의.

### 3.3 좌표계 (미터, Y가 위)
- GLB 기본 장면은 `scenes[1]`(노드 365개). 단위 1 = 1m. 북쪽 = −Z, 남쪽(정면) = +Z, 동쪽 = 0 쪽(오른쪽), 서쪽 = −X.
- 건물 바닥 면적: x −12.4 ~ 0, z −17.5 ~ 0.
- 바닥 윗면 높이: 지하 −6.6 / 1층 0 / 2층 3.65 / **3층 7.25** / 4층 10.75 / 지붕 14.1.
- 지하 본당 내부: x −13.03 ~ 0.63, z −17.58 ~ 0.08. 무대(Stage_Tier_0)가 북서쪽 모서리 x −13~−7.4, z −17.5~−11.9. 의자는 무대 모서리(−13, −17.5)를 중심으로 한 **부채꼴**.
- 남쪽 벽(`Wall_South_L/R`)에 x −8.2 ~ −4.2 의 4m 틈(입구). **홀로 들어가는 문은 모델에 따로 없다.**
- 외부 십자가 탑(`CROSS_*.001`)은 띄워진 게 아니라 `FRONT_BELT`/`SIDE_BELT` 위에 얹혀 있다(확인함). 문제 없음.

### 3.4 재질 공유 함정 (고친 버그)
GLTFLoader는 같은 재질 번호를 쓰는 메시가 **재질 객체를 공유**한다. 원본 코드는 본당 단면 모드에서 `Wall_South/East/Ceiling/ROOF` 재질의 투명도를 바꿨는데, `MAT_B1_WallWarm`은 자모실 벽·방송실 벽·방송 데스크도 같이 쓰고 있어서 **그것들이 같이 유령처럼 투명해졌다.** 이게 "자모실·방송실이 전혀 안 보인다"의 원인이었다. 투명 처리하는 메시는 재질을 `clone()`해서 따로 쓰도록 고쳤다. 앞으로 재질 투명도·색을 건드릴 때 같은 함정을 조심할 것.

## 4. 이번 세션에서 index.html에 한 일

코드 위치는 문자열로 검색하면 된다.

1. **이름/제목:** "우리교회" → "물댄동산교회".
2. **투어 5단계 추가 — "5. 3층 식당·소그룹실"** (`TOUR_WAYPOINTS.step5`): 4층·지붕을 숨기고 위에서 내려다본다(`hideTop`).
3. **3층 가구** (`// ===F3-BEGIN===` ~ `// ===F3-END===`):
   - 도면 평면을 모델 크기에 맞춰 옮긴 헬퍼 `planX`, `planZ` (가로 ×0.4986, 세로 ×0.949).
   - 식당: 식탁 3열×3줄(열 간격 1.6m), 한 식탁에 양쪽 3명씩, 식판. 배식대는 주방 벽에 붙임.
   - 주방(중앙 조리대, 출입문 1.0m + 배식구), 화장실·창고 벽, 소그룹실 1·2·3(식탁 1 + 의자 4, 문 1.0m), 이름표 스프라이트, 3층 조명.
4. **버튼 3개:** "🍚 식당에서 밥먹기"(앉아서 숟가락질 애니메이션, `isEating`), "💬 소그룹실 앉기", 기존 "🙏 자리에서 기도"는 앉은 채로 동작.
5. **본당 보정** (`function applyB1Fixes`, GLB 로드 직후 호출. GLB 파일은 건드리지 않고 화면이 열릴 때 코드로 고침):
   - 의자: 원본 42개를 숨기고 `layoutPews()`로 새로 계산해 복제 배치 → **56줄(112석)**. 겹침·벽/무대 침범 0. 줄 간격 1.2m, 통로 2곳(30°, 58°).
   - 십자가: 허공에 떠 있던 것을 무대 위 받침에 세움(LED 화면 앞, 위치 −12.45, −15.35).
   - LED 화면: 양 끝이 벽 밖으로 나가던 것을 폭 0.52배로 줄여 모서리 안쪽으로 이동.
   - 강대상: 바닥에서 9cm 떠 있던 것을 내림.
   - **자모실:** 원래 폭 0.6m(캐릭터가 못 들어감)였던 것을 칸막이를 x=−0.9로 옮겨 약 1.5m로 넓히고, 유리창·문(z −12.0~−11.0)·바닥 매트·아기침대 3개·장난감·이름표.
   - **방송실(엔지니어룸):** 원래 벽 1장뿐이던 것을 홀 쪽 유리창, 서/동쪽 벽, 동쪽 문(z −1.15~−0.3), 믹싱 데스크, 모니터 3, 장비 랙 2, 의자로 구성. 방송 데스크(원본 `Control_Desk`)는 홀 쪽에 그대로.
6. **앉기 높이 보정:** 의자 윗면 위로 캐릭터 몸통 바닥이 오도록(본당 의자 y −6.09, 3층 의자 7.25+0.26). 원본은 몸이 의자 속에 4~30cm 파묻혀 앉았다.
7. **본당 시점:** 원래 건물 밖 낮은 위치에서 벽을 통해 보게 되어 답답했다. 이제 4단계는 **위에서 비스듬히 내려다보는 단면 시점**(`camPos −3.5, 9.5, 8.5`)이고, 본당 밖 건물/주변/3층 가구는 숨기고(`hideOutside`) 북·서쪽 벽도 반투명 처리한다. *이 변경은 마지막에 한 것이라 화면으로 확인되지 않았다.*
8. 시작점/방향: 4단계 시작 위치를 방송 데스크와 안 겹치게 (−5.5, −3.3)으로, 바라보는 방향을 무대 쪽(`−π×0.86`)으로. (원본은 반대쪽을 보고 있었다. 계산상 약 60° 어긋남)
9. 클릭 이동 바닥 판정에 3층(y 7.0~7.6) 추가.

## 5. 검증한 것 / 못 한 것 (정직하게)

**했다 (계산·시뮬레이션):**
- 본당 의자 ↔ 벽/무대/데스크/강대상 충돌: 0건. 의자끼리 겹침: 0건. (SAT 검사)
- 캐릭터 폭 0.56m 기준 도달 가능성(격자 BFS): 본당 의자 112자리 전부 접근 가능, 자모실·방송실·무대 진입 가능. 폭 0.7m로도 동일. 3층 식당·주방·소그룹실 3곳·화장실 진입 가능(폭 0.8m에서는 화장실 문 0.75m만 막힘).
- 모든 빌더 코드를 가짜 THREE로 돌려 런타임 오류 없음 확인, `node --check` 구문 검사 통과.

**못 했다:**
- **실제 렌더링 화면 확인을 한 번도 못 했다.** 채팅 샌드박스에서 three.js를 받을 수 없었고(네트워크 차단), Chrome 확장 연결도 안 됐다. 위치·색·시점은 전부 수치 검산이다. **첫 작업으로 실제 화면을 확인해 달라.** 특히: 십자가가 받침 위에 서 있는지 / 자모실·방송실이 보이는지 / 4단계 위에서 보는 시점이 적당한지 / 3층 식탁 간격.
- 캐릭터는 **벽·가구와 충돌하지 않는다**(원본 방식). 클릭한 지점으로 직선으로 걷는다. "통로가 충분하다"는 건 눈으로 지나가는 것처럼 보인다는 뜻이다. 필요하면 충돌/경로 찾기를 추가해야 한다.

## 6. 미해결 / 사용자에게 물어볼 것

1. **본당 좌석 목표 수.** 지금 112석(의자 줄당 2명). 모델 본당이 도면의 42% 크기라 실제 규모 좌석 수는 못 낸다. "동시에 몇 명이 앉아야 하나"를 물어야 한다. 부족하면 B안(본당 확대)을 논의.
2. **본당 출입문.** 모델에 홀로 들어가는 문이 없다(남쪽 틈은 방송실 쪽). 실제 도면은 계단실 #1·#2로 들어온다. 문/계단 입구를 만들지 결정 필요.
3. 사용자가 이 index.html을 **지금 어떻게 열고 있는지**(로컬 서버? 어떤 도구?)와 vendor 폴더 위치.
4. 사용자가 말한 "자모실 = 유아실(B103)", "엔지니어룸 = 방송실(B104)"로 이해하고 작업했다. 틀리면 알려달라고 할 것.

- `build_index.py`, `build_preview.py` — 원본 church_tour.html에 조각을 끼워 index.html을 만들고(경로는 채팅 샌드박스 기준이라 수정 필요), 미리보기용 단일 파일을 만든 스크립트. **앞으로는 index.html을 직접 고치는 편이 쉽다.**
- `mock_run.js`, `f3_run2.js` — 가짜 THREE로 빌더를 돌려 오류/좌표를 확인한 스크립트.

## 9. 환경 메모

- 채팅 샌드박스는 외부 네트워크(npm/pip/CDN)가 막혀 있었다. Claude Code에서는 다를 수 있으니 three.js를 직접 받아 `vendor/three/`를 만들고 Playwright 등으로 캡처해 확인하는 것을 권한다.
- 파일 인코딩 UTF-8, 한국어 주석/문구 그대로 유지.
- 도면 PDF·GLB는 사용자 소유 자료다. 외부에 공개/업로드하는 작업(배포 포함)은 사용자에게 먼저 확인.
