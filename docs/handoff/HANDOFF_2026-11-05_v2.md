## 0. 사용자와 일하는 방식 (가장 중요)

- 사용자(혜연)는 **코딩을 모른다.** 한국어로, 쉬운 말로 짧게 말한다. **질문은 한 번에 하나만.**
- 작업이 끝나면 스크린샷을 보여 주고 **"마음에 들어요?"** 하고 묻는다.
- 사용자는 휴대폰 화면 캡처로 문제를 알려 준다. 빨간 동그라미가 문제 위치다.
- **배포(사이트 반영)는 사용자가 "반영해줘/배포해줘"라고 할 때만** 한다.
- 솔직하게 답한다. 검사에서 문제가 나오면(예: 스피커가 십자가를 가림) 숨기지 않고 말한 뒤 고친다.
- 사용자가 중간에 멈추고 "이 정도면 충분해"라고 하면 확인 안 된 작업은 넣지 않는다. 보관만 해 둔다.

## 1. 지켜야 할 규칙

1. **Supabase Secret 키(secret / service_role)는 절대 받지 않는다.** 사용자가 붙여 넣으면 지우라고 하고 Publishable 키만 쓴다.
2. **건물 GLB 파일(`church-model-release-20261104.glb`)은 고치지 않는다.** 설계도에 "건축물의 형태·평면·색상·재료 임의 수정 또는 변경 금지"라고 적혀 있다. 보정은 모두 **index.html 코드에서 화면에 그릴 때만** 한다.
3. 도면 PDF는 공개 저장소에 올리지 않는다.
4. 실제 찬송 음원이나 저작권이 남은 가사는 쓰지 않는다. 지금 반주는 코드로 만든 하프 소리이고, 저작권이 끝난 옛 찬송 4곡만 쓴다.
5. PR은 사용자가 말할 때만 만든다.

## 3. 지금까지 만든 것 (기능 목록)

**공간**
- 지하 본당: 대각선 무대(2단 강대상), 나무 스크린 벽과 LED 스크린, 서쪽 벽 십자가(간접 조명), 피아노와 드럼, 장의자 112석(전부 앉을 수 있음), 천장 조명 레일, **천장 라인어레이 스피커(새로 추가, 미배포)**, 자모실 벽, 기도제목 게시판(동쪽 벽)
- 1층: 필로티와 광장, 횡단보도(90도 보정), 자동차 바퀴
- 2층: 소예배실, 창가 쪽 큰 사무실, 동쪽은 트인 로비(소파, 벽에 붙은 정수기), 기도제목 게시판(복도 벽)
- 3층: 식당(앉아서 밥 먹기), 소그룹실 1~3
- 4층: 목양실, 아동부 예배실, 그룹실, 하늘이 트인 옥상 정원(도면 A-305 기준)
- 엘리베이터: 십자가 탑 안 한 곳, 모든 층에 있음. 가까이 가면 "몇 층으로 갈까요?" 창이 뜸

**캐릭터와 움직임**
- 처음 들어올 때 이름과 남/여를 고르고, 기기별로 기억함 (localStorage `mdc_name`, `mdc_gender`)
- 화면을 눌러 그 자리로 이동(주 방식, 길찾기 A*) + 폰 조이스틱
- 카메라는 캐릭터 뒤 눈높이. 벽이 가리면 벽을 반투명하게 함(카메라가 갑자기 튀지 않음). 두 손가락이나 휠로 확대/축소
- 앉기(장의자, 식당 의자, 소그룹실 의자, 로비 소파), 일어서기, 기도(눈 감고 손 모음 + 위에서 빛), 식사
- 행동 버튼은 그 층에 도착했을 때만 페이드인으로 나타남

**함께하기 (Supabase Realtime)**
- 같은 링크로 들어온 사람이 보이고, 접속 인원이 표시되고, 들어오고 나갈 때 알림이 뜸 (층 이동 때는 안 뜸)
- 채팅, **음성 메시지**(🎤 길게 누르기, 같은 층 사람에게만 들림)
- 방 불 켜기 상태도 공유됨
- 연습 모드: 주소에 `?net=local`을 붙이면 같은 브라우저의 창끼리 연결됨 (검사용). `?room=이름`으로 방을 나눔

**기도제목**
- 강대상 앞에 가면 "📝 기도제목 쓰기", 분류 선택, 이름 또는 익명으로 올리기
- **지금은 각자 기기에만 저장됨**(localStorage `mdc_prayers`). 다른 사람과 공유하려면 Supabase 테이블이 필요함 (남은 일 참고)

**소리와 빛**
- 하프 반주 4곡: 나 같은 죄인 살리신(사용자가 준 F장조 코드), 만복의 근원, 예수 사랑하심은, 고요한 밤
- 밤 모드: 저녁 7시~아침 6시 자동 전환(`?time=night` / `?time=day`로 강제 가능). 창이 따뜻하게 빛나고, 바깥 십자가가 켜지고, 건물 벽과 광장과 본당에 간접 조명이 들어옴
- 밤 나무 조명: 나무 밑 바닥 빛과 잎이 은은하게 밝아짐
- 소그룹실 1~3과 4층 그룹실에 "💡 불 켜기/끄기" 버튼

## 4. 남은 일 / 사용자에게 받을 답

1. **(답 기다리는 중) 옥상 쇠창살 높이.** 측정값: 지붕 14.1m, 앞쪽 세로 쇠창살(`LEFT_FACADE_TALL_FIN_*`)과 십자가 탑(`CROSS_TOWER_CORNER001`)은 16m, 뒤쪽 돌기둥(`BACK_STONE_FIN001`, `RIGHT_STONE_END_PIER001`)은 15m, 서쪽 기둥(`WEST_STONE_PIER001`)은 16.06m. 사용자에게 물어본 것: 쇠창살을 **(가) 뒤쪽 돌기둥 높이 15m**로 맞출지, **(나) 지붕 높이**로 낮출지. 건물 모양을 바꾸는 일이라 규칙 2(저작권 문구)를 함께 안내했다. 고친다면 GLB는 그대로 두고 코드에서 화면에 그릴 때만 바꾼다(scale.y/position 조정).
2. **바깥 십자가 위치.** `CROSS_VERTICAL001`(높이 12.4~14.6m)과 `CROSS_HORIZONTAL001`이 탑 꼭대기(16m)보다 1.4m 아래에 있다. 탑 위쪽으로 올리기로 안내했다(2번과 같이 진행).
3. **AI 음악 파일로 찬양 바꾸기.** 사용자가 mp3를 주면 `assets/music/` 같은 폴더에 넣고 하프 합성 대신 차례로 재생한다(재생 버튼은 기존 🔊 토글을 그대로 쓴다). 안내한 것: 한 곡 5MB 이하, AI 서비스 약관에서 공개 사용이 되는지 확인, 가사는 옛 찬송이나 직접 쓴 것만.
4. **나무 밑 바닥 조명 2판** (사용자의 원래 뜻 = "나무 밑 바닥에 등이 있어서 간접 조명처럼"). 땅에 묻힌 등, 등 둘레 바닥 빛, 줄기를 타고 올라가는 빛줄기를 만들던 중 사용자가 "이 정도면 충분해"라고 해서 배포하지 않았다. 코드는 `docs/handoff/pending/tree-uplight-v2.patch`에 있다(검사 안 됨). 사용자가 다시 원하면 적용하고 검사한다.
5. **실제 기기 두 대로 확인할 것** (컨테이너에서는 supabase.co에 접속할 수 없어서 아직 확인 못 함): 👥 접속 2명 표시, 채팅, 음성 메시지, 불 켜기 공유.
6. **기도제목을 모두와 공유하기.** Supabase에 테이블과 RLS 정책을 SQL로 만들고(사용자에게 대시보드 SQL Editor에 붙여 넣는 법을 한 단계씩 안내), `PrayerStore`의 저장과 불러오기를 Supabase로 바꾼다. `PrayerStore`는 이미 따로 분리해 두었다.

## 6. 검사하는 법 (Claude용)

```bash
cd /path/to/mdc && python3 -m http.server 8008   # 백그라운드로, 시간 제한은 길게
node tools/walk-check/spkocc.cjs                  # 예: 스피커가 십자가/스크린을 가리는지 (광선 검사)
```
- Playwright와 chromium은 컨테이너에 이미 깔려 있다. 실행 옵션은 `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`.
- 검사 전에 localStorage에 `mdc_name`과 `mdc_gender`를 넣어야 한다. 안 넣으면 처음 뜨는 선택 창이 화면을 막는다.
- 창을 3개 이상 띄우면 느려지니 `goto`에 `waitUntil:'domcontentloaded', timeout:120000`을 준다.
- 검사가 끝나면 `docs/verification/2026-11-05/REPORT.md`에 짧게 적고 스크린샷을 같이 넣는다.
